# Склад — учёт остатков

Мобильное веб-приложение для учёта остатков на складе. Замена громоздкой
Excel-таблицы: крупные кнопки под палец, все средние и рекомендации по заказу
считаются сами — формулы писать не нужно.

Работает офлайн, без сборки и зависимостей (чистый HTML/CSS/JavaScript).

## Что умеет

- **Этажи** — несколько этажей, у каждого свой остаток; категории и товары общие.
  Быстрое переключение чипами вверху экранов «Обзор», «Ввод», «Товары»,
  «Аналитика». Управление этажами — во вкладке «Ещё».
- **Перенос между этажами** — в карточке товара «🔀 Перенести на другой этаж»:
  выбираете, сколько единиц, — здесь уменьшается, там появляется. Переносы не
  считаются расходом/приходом (это перемещение), поэтому средние не искажают.
- **Категории и товары** — категории (напр. «Молочные продукты») и товары-подкатегории
  внутри них.
- **Поиск** — на вкладке «Товары» строка поиска фильтрует по названию товара и
  категории на лету (совпадение по категории показывает все её товары).
- **Сворачивание категорий** — тап по шапке категории сворачивает/разворачивает её
  список; есть «Свернуть все / Развернуть все». Состояние запоминается между
  сессиями. Во время поиска категории всегда раскрыты.
- **Приход и расход по дням** — быстрый ввод за выбранный день большими кнопками
  «Приход» / «Расход» (на выбранный этаж). Остаток пересчитывается автоматически.
- **Остаток на текущий день** — по каждому товару и суммарно по категории.
- **Средний расход** — в день, за неделю и за месяц; можно считать **только по
  рабочим дням** (набор рабочих дней настраивается).
- **Минимальный остаток** для заказа — порог по каждому товару.
- **Список заказа** — на вкладке «Аналитика» показывается **список** «что и сколько
  заказать» по позициям (напр. «Молоко +10 л, Сахар +25 кг»), а не одна сумма —
  единицы у товаров разные.
- **Отчёт за период** — на «Аналитике» выбираете диапазон дат и видите приход и
  расход по каждому товару и категории за этот период.
- **Насколько срочно** — метка «Срочно / Скоро / В норме» и оценка «на сколько дней
  хватит».
- **Инвентаризация** — задать фактический остаток, разница уходит в историю.
- **Импорт из Excel** — загрузите свою `.xlsx`-таблицу учёта, приложение само
  разберёт категории, товары, текущие остатки и расход за период (см. ниже).
- **Синхронизация между устройствами** — телефон и ноутбук видят одни и те же
  данные через ваш сервер (см. «Сервер и синхронизация»). Работает офлайн-первым:
  данные всегда на устройстве, синк идёт фоном.
- **Резервная копия** — экспорт/импорт всех данных в файл.

## Как это считается

Вся «математика» вынесена в один файл [`assets/calc.js`](assets/calc.js) и покрыта
тестами — поэтому средним и рекомендациям можно доверять.

- **Средний расход в день** = сумма расхода за окно усреднения (по умолчанию 30 дней)
  ÷ число дней в окне. В режиме «только рабочие дни» делитель — количество рабочих дней.
  Пока данных мало, окно не уходит левее первого движения (среднее не занижается).
- **За неделю** = средний в день × число рабочих дней (или × 7).
- **За месяц** = средний в день × рабочих дней в месяце (или × 30).
- **На сколько хватит** = текущий остаток ÷ средний расход в день.
- **Заказать на месяц** = месячный расход + мин. остаток − текущий остаток (округление вверх).
- **Срочность**: `Срочно` — задан минимум и остаток ≤ минимума, либо при текущем
  расходе запаса < 7 дней; `Скоро` — запаса < 21 дня или близко к минимуму; иначе
  `В норме`. Позиция без расхода и без заданного минимума считается «В норме».

## Экраны

- **Обзор** — что и как срочно заказать, остаток по категориям.
- **Ввод** — быстрый ввод прихода/расхода за день.
- **Товары** — категории, товары, остатки; карточка товара со всей аналитикой.
- **Аналитика** — средние по категориям и товарам, сумма заказа на месяц.
- **Ещё** — рабочие дни, окно усреднения, резервная копия, демо-данные.

## Запуск

Локально (без сервера): откройте `index.html` в браузере — приложение работает,
но данные только на этом устройстве.

Онлайн: **фронтенд хостится на GitHub Pages** — `https://y-gagar1n.github.io/sklad/`
(статика раздаётся из репозитория, `.nojekyll`). Откройте этот адрес на телефоне и
добавьте на домашний экран («Поделиться» → «На экран Домой») — приложение
откроется на весь экран, работает офлайн. **Данные синхронизируются через свой
сервер** на VM (адрес синка по умолчанию **https://213-165-212-180.sslip.io**,
см. «Сервер и синхронизация»). Фронт и API на разных origin, поэтому на сервере
включён CORS.

## Импорт из Excel

Вкладка «Ещё» → «Импорт из Excel (.xlsx)». Парсер (`assets/xlsx-import.js`)
читает книгу без сторонних библиотек (распаковка ZIP через встроенный
`DecompressionStream`, разбор XML) и по каждому листу берёт колонки **по
заголовкам**, а не по буквам столбцов (раскладка на листах разная):

- `Категория` → категория (у листов «Хоз-ка» её нет → категория «Хозтовары»);
- `наименование` → товар;
- `ост итого` / `Остаток на конец мес-ца` → текущий остаток;
- `Итого расход за неделю` / `…за месяц` → расход за период (для среднего).

Ежедневные `Приход`/`Расход` намеренно **не** берутся — в исходных таблицах они
заполняются непоследовательно. По каждому товару остаток и расход берутся из
самого свежего листа, где они указаны (это исключает двойной учёт при
пересечении недельных и месячного листов). Недельный итог расхода
раскладывается на последние 5 рабочих дней, месячный — на ~22, чтобы средние
считались сразу. Категории с одинаковым названием в разном регистре
объединяются (`Соль` = `соль`). Требуется браузер с `DecompressionStream`
(iOS 16.4+, свежий Chrome). Импорт заменяет текущие данные — при необходимости
сначала сделайте резервную копию.

## Сервер и синхронизация

Один Go-бинарь ([`backend/`](backend/)) держит API синхронизации по HTTPS с
валидным сертификатом Let's Encrypt (авто-выпуск через `autocert`, TLS-ALPN-01
на :443, домен вида `213-165-212-180.sslip.io` — покупать домен не нужно). Он
умеет и раздавать сам веб-апп (флаг `-static`, как резервный вариант), но
основной фронт живёт на **GitHub Pages** — это другой origin, поэтому на сервере
включён **CORS**: разрешённые origin'ы задаются `-cors-origin` / env
`SKLAD_CORS_ORIGIN` (через запятую; по умолчанию — origin Pages
`https://y-gagar1n.github.io`; пусто — любой). Авторизация всё равно по
bearer-токену в заголовке (не cookie), поэтому даже `*` безопасен. Сервис
полностью изолирован от соседнего `todo-sync` (свой пользователь `sklad-sync`,
каталоги `/opt|/var/lib|/etc|/var/backups/sklad-sync`, порт 443).

**Модель синка.** У каждой записи есть `updatedAt` (штампуется при каждой правке)
и `deleted` (тумбстоун вместо удаления). Конфликты решаются whole-record LWW по
`updatedAt`, одинаково для всех коллекций; движения иммутабельны, поэтому их
слияние — это union по id. Сервер «тупой»: хранит записи как есть и отдаёт дельту
по монотонному `seq`-курсору. Вся логика — на клиенте (`assets/sync.js`),
устройство-локальные вещи (активный этаж, свёрнутые категории, адрес/токен) не
синкаются. Данные лежат локально в `localStorage`, синк идёт фоном (после правок,
при возврате в приложение и появлении сети) и вручную кнопкой.

**Развёртывание** (с dev-машины, у которой есть SSH к VM):

```bash
./bootstrap-sklad.sh                 # разово: токен + домен + CORS-origin → /etc/sklad-sync/env
./deploy-sklad.sh                    # собрать, залить бинарь+статику+юниты, запустить
```

`bootstrap-sklad.sh` сгенерирует токен (или возьмёт из `~/.config/sklad-sync/token`)
и выведет его — этот токен вводится в приложении; заодно кладёт `SKLAD_CORS_ORIGIN`
(origin Pages) в env. `deploy-sklad.sh` кросс-компилит бинарь, кладёт веб-файлы в
`/opt/sklad-sync/public` (резервная раздача), ставит systemd-юниты и суточный
бэкап, проверяет, что порт 443 не занят чужим сервисом. Требуется, чтобы порт 443
был открыт в фаерволе.

**Фронт на GitHub Pages.** В настройках репозитория Settings → Pages источником
указывается ветка с этими файлами (в корне лежат `index.html` и `.nojekyll`). Апп
открывается по `https://y-gagar1n.github.io/sklad/`; все пути относительные,
поэтому работает из подпапки без правок.

**Подключение устройства.** Открыть апп на Pages, «Ещё» → «Синхронизация»: адрес
сервера синка + токен → «Сохранить и проверить». На первом устройстве данные уедут
на сервер обычным синком. На втором (пустом) устройстве — «Заменить локальные
данными с сервера», чтобы стать зеркалом, дальше оба синкаются автоматически.

## Тесты

```bash
./test.sh                       # JS: node:test, без зависимостей
cd backend && go test -race ./... # бэкенд: LWW, курсор, /sync, /wipe, авторизация, гонки
```

JS-тесты (`tests/*.test.mjs`): логика расчётов (`calc`), разбор Excel
(`xlsx-import`), хранилище и этажи (`store`), а также синхронизация (`sync`) —
слияние по LWW, тумбстоуны, pull-replace, полный round-trip клиента против точной
модели сервера.

## Структура

```
index.html                 оболочка приложения
assets/
  calc.js                  чистая логика (средние, остатки, заказ)
  store.js                 данные, localStorage, updatedAt/тумбстоуны, экспорт записей
  sync.js                  клиент синхронизации (pull → merge → push, LWW)
  app.js                   интерфейс: экраны, формы, навигация, UI синка
  xlsx-import.js           разбор .xlsx без зависимостей
  styles.css               мобильный дизайн
manifest.webmanifest       PWA-манифест
sw.js                      service worker (офлайн)
icons/                     иконки (+ генератор gen-icons.mjs)
backend/
  main.go                  сервер: раздача аппа + API синка + autocert
  deploy/                  systemd-юниты и backup.sh (namespace sklad-sync)
deploy-sklad.sh            деплой на VM (изолирован от todo)
bootstrap-sklad.sh         разовая настройка секретов на VM
tests/*.test.mjs           тесты (calc, store, sync, xlsx-import)
```
