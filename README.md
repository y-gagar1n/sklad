# Склад — учёт остатков

Мобильное веб-приложение для учёта остатков на складе. Замена громоздкой
Excel-таблицы: крупные кнопки под палец, все средние и рекомендации по заказу
считаются сами — формулы писать не нужно.

Работает офлайн, без сборки и зависимостей (чистый HTML/CSS/JavaScript).

## Что умеет

- **Этажи** — несколько этажей, у каждого свой остаток; категории и товары общие.
  Быстрое переключение чипами вверху экранов «Обзор», «Ввод», «Товары»,
  «Аналитика». Управление этажами — во вкладке «Ещё».
- **Перенос между этажами** — в карточке товара «🔀 Перенести на другой этаж»:
  выбираете, сколько единиц, — здесь уменьшается, там появляется. Переносы не
  считаются расходом/приходом (это перемещение), поэтому средние не искажают.
- **Категории и товары** — категории (напр. «Молочные продукты») и товары-подкатегории
  внутри них.
- **Приход и расход по дням** — быстрый ввод за выбранный день большими кнопками
  «Приход» / «Расход» (на выбранный этаж). Остаток пересчитывается автоматически.
- **Остаток на текущий день** — по каждому товару и суммарно по категории.
- **Средний расход** — в день, за неделю и за месяц; можно считать **только по
  рабочим дням** (набор рабочих дней настраивается).
- **Минимальный остаток** для заказа — порог по каждому товару.
- **Список заказа** — на вкладке «Аналитика» показывается **список** «что и сколько
  заказать» по позициям (напр. «Молоко +10 л, Сахар +25 кг»), а не одна сумма —
  единицы у товаров разные.
- **Отчёт за период** — на «Аналитике» выбираете диапазон дат и видите приход и
  расход по каждому товару и категории за этот период.
- **Насколько срочно** — метка «Срочно / Скоро / В норме» и оценка «на сколько дней
  хватит».
- **Инвентаризация** — задать фактический остаток, разница уходит в историю.
- **Импорт из Excel** — загрузите свою `.xlsx`-таблицу учёта, приложение само
  разберёт категории, товары, текущие остатки и расход за период (см. ниже).
- **Резервная копия** — экспорт/импорт всех данных в файл (перенос на другой телефон).

## Как это считается

Вся «математика» вынесена в один файл [`assets/calc.js`](assets/calc.js) и покрыта
тестами — поэтому средним и рекомендациям можно доверять.

- **Средний расход в день** = сумма расхода за окно усреднения (по умолчанию 30 дней)
  ÷ число дней в окне. В режиме «только рабочие дни» делитель — количество рабочих дней.
  Пока данных мало, окно не уходит левее первого движения (среднее не занижается).
- **За неделю** = средний в день × число рабочих дней (или × 7).
- **За месяц** = средний в день × рабочих дней в месяце (или × 30).
- **На сколько хватит** = текущий остаток ÷ средний расход в день.
- **Заказать на месяц** = месячный расход + мин. остаток − текущий остаток (округление вверх).
- **Срочность**: `Срочно` — задан минимум и остаток ≤ минимума, либо при текущем
  расходе запаса < 7 дней; `Скоро` — запаса < 21 дня или близко к минимуму; иначе
  `В норме`. Позиция без расхода и без заданного минимума считается «В норме».

## Экраны

- **Обзор** — что и как срочно заказать, остаток по категориям.
- **Ввод** — быстрый ввод прихода/расхода за день.
- **Товары** — категории, товары, остатки; карточка товара со всей аналитикой.
- **Аналитика** — средние по категориям и товарам, сумма заказа на месяц.
- **Ещё** — рабочие дни, окно усреднения, резервная копия, демо-данные.

## Запуск

Локально: откройте `index.html` в браузере (двойной клик).

Онлайн через **GitHub Pages** (сайт статический, сборка не нужна). Один раз
включить: **Settings → Pages → Source: «Deploy from a branch»**, ветка
`claude/warehouse-inventory-app-e7s489`, папка `/ (root)` → **Save**. Файл
`.nojekyll` в корне заставляет Pages отдавать файлы как есть. Адрес:
**https://y-gagar1n.github.io/sklad/**

На телефоне откройте адрес и добавьте на домашний экран («Поделиться» → «На экран
Домой») — приложение откроется на весь экран и будет работать офлайн.

## Импорт из Excel

Вкладка «Ещё» → «Импорт из Excel (.xlsx)». Парсер (`assets/xlsx-import.js`)
читает книгу без сторонних библиотек (распаковка ZIP через встроенный
`DecompressionStream`, разбор XML) и по каждому листу берёт колонки **по
заголовкам**, а не по буквам столбцов (раскладка на листах разная):

- `Категория` → категория (у листов «Хоз-ка» её нет → категория «Хозтовары»);
- `наименование` → товар;
- `ост итого` / `Остаток на конец мес-ца` → текущий остаток;
- `Итого расход за неделю` / `…за месяц` → расход за период (для среднего).

Ежедневные `Приход`/`Расход` намеренно **не** берутся — в исходных таблицах они
заполняются непоследовательно. По каждому товару остаток и расход берутся из
самого свежего листа, где они указаны (это исключает двойной учёт при
пересечении недельных и месячного листов). Недельный итог расхода
раскладывается на последние 5 рабочих дней, месячный — на ~22, чтобы средние
считались сразу. Категории с одинаковым названием в разном регистре
объединяются (`Соль` = `соль`). Требуется браузер с `DecompressionStream`
(iOS 16.4+, свежий Chrome). Импорт заменяет текущие данные — при необходимости
сначала сделайте резервную копию.

## Данные

Данные хранятся локально в браузере устройства (`localStorage`). Синхронизации
между устройствами нет — для переноса используйте «Сохранить копию» / «Загрузить
из файла» во вкладке «Ещё». Делайте резервную копию перед крупными изменениями.

## Тесты

```bash
./test.sh          # или: npm test
```

Тесты (`tests/calc.test.mjs`) на встроенном `node:test`, без зависимостей —
проверяют даты, остатки, средние, рекомендации по заказу и срочность.

## Структура

```
index.html                 оболочка приложения
assets/
  calc.js                  чистая логика (средние, остатки, заказ) — покрыта тестами
  store.js                 данные и хранение (localStorage), экспорт/импорт
  app.js                   интерфейс: экраны, формы, навигация
  styles.css               мобильный дизайн
manifest.webmanifest       PWA-манифест
sw.js                      service worker (офлайн)
icons/                     иконки (+ генератор gen-icons.mjs)
tests/calc.test.mjs        тесты логики
```
